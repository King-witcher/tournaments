# Avisos no Discord

Decidido pelo usuário: **webhook por comunidade**; o owner cola a URL do webhook de um canal e o site posta lá. Nada de bot nem DM. Email: nenhum aviso de torneio por enquanto (a cota do Resend, 100 por dia, fica para a conta). O resto é decisão minha, fácil de mudar.

- **Todo torneio publicado avisa**, também o de inscrição só por link (a decisão de tirar o "esconder" torneio tirou o filtro daqui). Push e tempo real também não filtram por inscrição.
- **Configuração** (`discord/`, `GET`/`PUT`/`DELETE /tenants/{slug}/discord` e `POST .../test`), só do owner, nas configurações da comunidade: URL, "Enviar teste", quais avisos, idioma das mensagens (pt/es), "mencionar jogadores" (ligado por padrão) e remover. Uma por comunidade (`discord_webhooks`). Não emite no outbox ao mudar (só o owner a vê).
- **A URL é credencial.** Só `https://discord.com/api/webhooks/{id}/{token}` e as variantes `discordapp.com`, `ptb.` e `canary.` (a API faz requisições para o endereço; qualquer outro host seria porta para serviços internos; o cliente também não segue redirecionamentos). Vai para o banco separada em id e token, em claro, porque a API precisa usá-la (guardar só o hash vale para segredo que a API só confere). A API devolve só o id; URL e token nunca saem em resposta nem no log (os erros do `reqwest` perdem a URL antes de logar).
- **Avisos** (cada um ligável; `events` guarda os códigos): check-in aberto, torneio iniciado (link da chave), partida pronta, hora de iniciar e mapa contestado (organização), torneio encerrado (pódio) e resultado de cada série (**desligado por padrão**, é muita mensagem). Os do veto: "adversário pronto" (para quem falta clicar; ligado numa configuração nova) e "veto começou" (os dois lados numa mensagem; desligado). O banco só confere a forma do código; quais existem é o `CATALOG` (`discord/catalog.rs`), então um aviso novo entra com **uma linha lá** (código do `Notice`, se vem ligado, a quem se dirige, texto pt e es) e uma chave `events.<código>` no `Discord.json` do front, sem migration. Configurações antigas não ligam o aviso novo sozinhas.
- **De onde vêm**: os `Notice` do Web Push e o evento do outbox `announce` (`outbox::Announce`: `tournament.started`, `tournament.finished`, `match.series_decided`, só para o canal, fora do OpenAPI e do front). A comunidade sai do primeiro segmento do `path`. O despachante põe na fila do Discord na mesma transação em que lê o outbox, num savepoint (falha da fila não derruba push nem tempo real).
- **Menção**: quem vinculou o Discord é mencionado (`<@id>`) em "partida pronta" (os dois lados numa mensagem) e nos avisos da organização, se "mencionar jogadores" está ligado. `allowed_mentions` lista só essas pessoas (`parse` vazio: nunca `@everyone`, `@here` nem cargos). Sem vínculo, o apelido; apelidos e nomes de torneio vão com Markdown e `@` escapados.
- **Fila própria** (`discord_messages`), esvaziada por uma tarefa da API (acordada pelo despachante e a cada 15 s): o Discord limita o ritmo por webhook (~5 mensagens por 2 s) e o despachante não pode esperar. Uma mensagem por vez, em ordem. 429 (`retry_after`) ou janela esgotada (`X-RateLimit-Remaining: 0`) põem **o webhook** em espera (`retry_at`); as outras comunidades seguem. Pelo menos uma vez: só sai da fila depois do 2xx, e a reserva de 2 minutos cobre quem cair no meio. 401/404: webhook apagado, a configuração fica `broken_at`, a fila é descartada, nada mais entra e a tela pede outra URL (colar nova desmarca). Outra falha (rede, 5xx): até 5 tentativas com espera de 30 s que dobra; 4xx: descarta com log. Mensagem com mais de 1 hora é descartada. Mensagens iguais se juntam só onde o catálogo diz (`merge`: partida pronta, que chega uma vez por lado).
- **"Enviar teste" usa o endereço do campo**: `POST .../test` aceita `url` e `locale` (mesma validação do `PUT`, `discord.url_invalid`; nunca devolvida nem logada). Com `url`, o teste vai para ela, salva ou não, sem mexer na configuração (um 404 não marca o webhook salvo como quebrado); sem, testa o salvo. O botão só habilita com a forma de um webhook do Discord.
- **Texto**: exceção à regra "a API devolve códigos": a mensagem sai da API para o Discord, então o catálogo pt/es fica em `discord/catalog.rs` (como o email). Descartado ler `web/messages` com `include_str!`: o Render compila só `backend/`. Links com `WEB_ORIGIN` e o idioma da configuração; nome do torneio na tradução daquele idioma quando houver.
- Sem variável de ambiente nova (`https://discord.com` só muda nos testes, `Webhooks::with_base`).
